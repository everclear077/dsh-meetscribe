# dsh-meetscribe 产品需求与交互设计

更新日期：2026-11-22
状态：v0.1 产品规范；以 README 和 TESTING.md 记录的实际实现/验证状态为准

> 当前新增 Harness 左侧 **MeetScribe** 独立工作台：默认显示全部 Word 纪要版本，支持文件名/会议名称/路径搜索、名称和时间正倒序、刷新与下载；识别设置位于同一工作台，不再出现在 Harness 设置页。纪要生成由 Host 后台任务执行，工作台实时显示完整阶段、模型推理/正文接收字符数、失败原因、重试和完成版本下载。“纪要生成模型”默认跟随 DSH，也可独立选择 Harness 已注册的模型和实际支持的推理强度；固定 120 秒总超时已改为可配置无响应超时。浮窗另提供“在 DSH 对话中整理”，将完整会议内容和 Markdown 纪要要求追加为 DSH 对话草稿，用户检查后主动发送，不自动生成 Word。

> 实现说明：本文保留产品目标和后续交互方向。当前版本的 Ctrl+E 会打开浮窗并自动使用系统默认麦克风开始/继续录音，再次按下只收起浮窗，不停止录音。浮窗不提供开始按钮或设备选择器，暂停/继续、清空与生成纪要使用顶部纯图标按钮，录音状态使用圆点表示。历史会议支持二次确认后的全部清空。浮窗通过 React Portal 挂载到页面顶层，避免被 Harness 左侧栏遮挡；它仍不是独立系统置顶窗口。文字识别使用插件直接下载的 SenseVoice Small Q8 GGUF + transcribe.cpp 0.4.1，不再使用 sherpa-onnx ASR；该模型非流式，临时文字来自分段快照，默认 800ms 静音后整段定稿。系统音频、拖动、位置记忆、改键、会后声纹校准等仍属后续方向，不视为已交付功能。

## 1. 产品目标

dsh-meetscribe 是面向会议记录场景的 DeepSeek Harness 插件，核心能力包括：

- Ctrl+E 全局唤起轻量实时识别浮窗；
- 插件自行下载并管理本地模型；
- 麦克风与系统声音同时采集；
- 多说话人分离、改名和会后校准；
- 原始逐字稿与整理视图；
- 一键调用 DSH 大模型并生成正式 Word 会议纪要。

第一阶段不追求翻译、声纹注册、手机端和任意网页听写，优先保证会议识别、说话人管理和 Word 输出稳定可靠。

## 2. 主流程

1. 用户点击 Harness 左侧 **MeetScribe**，进入工作台的“识别设置”，点击“检查并准备模型”，由插件下载并校验 ASR、VAD 和已启用的声纹模型；有效缓存会直接复用。
2. 用户按 Ctrl+E，浮窗立即出现，自动创建或继续会议并请求系统默认麦克风权限。
3. 模型就绪后开始本地识别；加载期间浮窗明确显示准备状态。
4. 实时声波反映实际采集音量；临时文字与整句文字持续显示。
5. 用户按需暂停或继续录音；最小化或收起浮窗不会中断采集。
6. 在展开视图中修改说话人姓名、合并标签或逐段重新指派。
7. 用户可选填写会议地点、主持人、记录人等元数据；字段独立滚动，保存和录音控制不被遮挡。
8. 如需重新记录，点击“清空”移除当前逐字稿和匿名说话人标签，同时保留会议信息与 Word 版本；录音中清空会自动继续。
9. 用户暂停录音后选择一种整理方式：点击“生成纪要”创建后台 Word 任务，或点击“在 DSH 对话中整理”创建完整对话草稿。
10. Word 路径由 DSH 大模型生成结构化内容，经校验后渲染为 `.docx`；独立工作台持续显示任务阶段，失败可重试。对话路径只在用户检查并发送草稿后调用模型，直接复用 DSH 对话结果。
11. 用户下载版本化 Word 文件，也可补充内容后重新生成新版本；对话草稿不自动进入 Word 版本列表。

## 3. 快捷键

### 3.1 默认行为

| 操作 | 默认行为 |
| --- | --- |
| Ctrl+E | 从关闭状态唤起浮窗并自动开始/继续录音；浮窗已展开时再次按下只收起，不停止录音 |
| Esc | 收起浮窗，不停止录音、不删除已识别内容 |
| 浮窗展开按钮 | 打开完整会议工作台 |
| 暂停/继续 | 暂停时释放采集并保留内容；继续时恢复系统默认麦克风采集 |
| 清空 | 清空当前逐字稿与匿名说话人标签，保留会议信息和已生成 Word 版本 |

当前版本快捷键固定为 Ctrl+E，不提供改键入口；关闭或最小化浮窗不等于结束录音。

### 3.2 全局快捷键要求

- DSH 窗口内使用 DSH shortcuts 服务。
- DSH 最小化或其他应用前台时，由 Windows 桌面助手注册全局 Ctrl+E。
- 注册失败时明确提示快捷键被占用。
- 其他软件与本插件同时注册 Ctrl+E 时会发生冲突，应明确提示；快捷键冲突解决和改键入口仍属后续方向。
- 不因快捷键冲突影响已经保存的会议数据。

## 4. 实时识别浮窗

### 4.1 视觉原则

- 无边框、圆角、轻阴影，保持紧凑轻量的视觉效果。
- 系统级置顶，默认不抢占用户当前输入焦点。
- 支持拖动、缩放、最小化和展开。
- 跟随 DSH 深色或浅色主题。
- 记住浮窗位置、大小和所在显示器。
- 动画仅用于音量、识别状态和临时文字更新。
- 可选“共享屏幕时隐藏浮窗”。

### 4.2 展开状态布局

顶部区域：

- 识别状态、会议名称和会议时长；
- 默认麦克风状态与真实音量声波；
- 最小化、展开和关闭按钮。

说话人管理位于展开视图正文上方，紧凑模式不显示：

- 我、发言人 1、发言人 2等标签；
- 点击姓名内联修改；
- 管理说话人入口；
- 标签过多时横向滚动或展开，不挤压主要控制按钮。

正文区域：

- 时间、说话人和文字；
- 临时结果使用灰色；
- 整句结果使用正常前景色；
- 不确定说话人、人工修改和识别失败使用不同轻量状态；
- 用户向上滚动时停止自动跟随；
- 提供“回到最新”。

顶部区域固定显示纯图标按钮：

- 暂停/继续；
- 一键清空当前逐字稿；
- 在 DSH 对话中整理：追加完整草稿，不自动发送；
- 后台生成 Word 纪要；录音中需先暂停才能使用任一整理路径。

录音、暂停和准备状态仅以圆点显示，具体含义保留在辅助名称与悬浮提示中。会议信息表单字段区域独立滚动，保存按钮不随字段滚出，顶部录音控制始终可见。

### 4.3 精简状态

仅显示：

- 标题栏中的识别状态、会议时长、最小化、展开和关闭；
- 真实音量声波与当前聆听/暂停状态；
- 逐字稿正文；
- 暂停/继续、清空和生成纪要按钮。

说话人管理与人工记录入口仅在展开视图显示。

### 4.4 取消与结束

必须区分：

- 取消当前尚未确认的一句话；
- 暂停会议；
- 结束整场会议；
- 删除会议记录。

结束会议不能等同于删除记录。危险操作需要明确确认。

### 4.5 左侧独立工作台

- Harness 左侧显示 MeetScribe 图标，点击后以 `main` 主界面打开，不是悬浮弹层；
- 默认“纪要文件”视图汇总全部会议的每一个 Word 生成版本；
- 列表显示文件名、所属会议、版本、生成时间与下载操作；
- 支持按文件名、会议名称或路径搜索，按时间最新/最早和名称正序/倒序排列；
- 空状态明确引导用户打开会议浮窗生成首份纪要，搜索无结果时可一键清除；
- 生成任务独立于文档列表显示：包含准备逐字稿、DSH 模型整理、解析和生成 Word 四阶段，模型阶段显示已接收字符数；
- 进行中数量同时出现在导航；关闭浮窗或切换工作台页面不取消任务，同会议重复点击不重复调用模型；
- 失败显示真实 Provider/解析/写入错误并可重试，完成后下载对应生成版本；删除或清空后同步移除旧任务；
- “识别设置”包含原 Harness 设置页的全部功能，设置页不再重复注册入口；
- 浅色、深色与窄屏布局保持可用，文档下载继续使用现有会议与版本白名单路由。

## 5. 模型设置与初始化

### 5.1 一键配置

依次执行：

1. 检查插件模型目录中的 ASR、VAD 和已启用的声纹模型是否完整；
2. 从固定地址下载缺失或不匹配的模型，ASR/VAD 主地址失败时尝试内置备用镜像，核对大小和 SHA-256 后加载；
3. 请求麦克风权限；
4. 检查系统声音回采；
5. 注册或验证全局快捷键；
6. 完成一次短录音、回放和识别测试；
7. 预热模型并进入可用状态。

任何一步失败都应给出具体修复入口，而不是只显示“初始化失败”。

### 5.2 模型管理

当前实现将 SenseVoice Small Q8、Silero VAD GGUF 和 ERes2NetV2 声纹模型统一下载到 `%LOCALAPPDATA%\dsh-meetscribe\models` 的 `asr`、`vad`、`speaker` 子目录。用户点击“检查并准备模型”后，插件按固定地址、精确文件大小和 SHA-256 准备模型；ASR/VAD 主地址失败时尝试内置备用镜像，校验要求保持一致。有效缓存直接复用，同一模型的重复任务共享 Promise；启动预加载只加载已经安装的 ASR/VAD，不会静默下载。录音中的声纹懒加载只校验并加载已安装文件，不触发下载。录音中需要先暂停再安装或修复模型，模型准备期间不能开始或继续录音。当前不提供自定义模型目录、自定义镜像、断点续传或模型删除界面。以下是完整模型管理方向，未全部视为当前已交付能力：

- 模型名称、用途、版本、文件大小和安装状态；
- 下载进度、失败重试和断点续传；
- 可配置镜像源；
- SHA-256 校验；
- 下载到临时文件，校验完成后原子替换；
- 自定义模型目录；
- 模型更新、损坏修复、重新下载和删除；
- 旧模型配置迁移；
- 模型许可证和来源记录；
- 手动卸载、会后卸载或常驻内存；
- GPU 开关和不可用时回退提示。

第一阶段通过“轻量会议包”“标准会议包”等预设隐藏模型组合复杂度，高级设置再展示各组件。

### 5.3 纪要 LLM 路由与等待策略

“识别设置 → 纪要生成模型”独立于上述本地 ASR/VAD/声纹下载管理：

- 默认“跟随 DSH 当前模型”；用户也可选择 Harness 当前注册的明确 Provider/Model，选择只影响之后新启动的 Word 任务，不覆盖 DSH 对话默认设置或重定向进行中任务。
- 模型列表直接来自 DSH 对话选择器使用的 `sessionController.modelCatalog()`，按 Provider 分组，并复用对话窗口的账号/官方 Provider 优先顺序和组内模型顺序；推理强度使用目录中的实际声明，不在插件中硬编码，没有声明 reasoning efforts 的模型只使用模型默认行为。目录读取失败时保留真实错误，不回退为另一份可能不同的自行枚举列表。
- 设置仅保存 provider、model 和可选 reasoningEffort，不保存 API Key、OAuth 或完整 Provider 配置。
- 默认无响应超时 5 分钟，可在 1–30 分钟内调整。任意思考、正文或其他流事件都会重置计时；它不是在持续生成时仍强制生效的总截止时间。
- 模型通道已失效或推理强度不受支持时，错误提供返回识别设置修复的明确路径；其他错误保留实际 Provider code/message。

## 6. 音频采集

当前版本只使用系统默认麦克风，不提供应用内设备或来源选择；更换设备需先修改 Windows 默认输入设备。采集链路包括：

- 默认麦克风输入；
- 回声消除、16 kHz 重采样与真实音量电平；
- 暂停时释放音频资源，继续时重新初始化默认设备。

系统声音回采、混合采集、指定设备选择、录音回放和设备热插拔策略仍是后续方向。当前 UI 不暴露这些未验证入口，也不宣称支持它们。

## 7. 本地识别

当前处理链路：

音频采集 → 连续 Silero VAD 开段与 800ms 静音切句（故障时 RMS 回退）→ SenseVoice 分段快照临时结果 → 完整段定稿 → ITN/术语纠正 → 说话人关联 → 浮窗及持久化。

VAD 模式下保留 1.5 秒滚动前置音频，低音量句子不依赖固定 RMS 门限开段。检测响应与 PCM 使用全局样本序号对齐，partial 不上传未检测尾部，final 只提交已确认的头部；在响应在途期间到达的尾部留给下一段，避免漏字或重复。VAD 判出的短语音直接交给 ASR，不再按 250ms 规则主动删除。

当前模型不支持原生流式，因此“临时结果持续更新”指有界间隔的快照刷新，不表示逐 token 输出。最终识别不再经过 Zipformer 或 sherpa-onnx SenseVoice。具体要求：

- 中文和中英混合识别；
- 临时结果持续更新，整段推理不得并发压垮同一模型；
- 停顿时提交整句，当前浏览器连续讲话分段上限约 12 秒；
- 原生推理异步执行，PCM 快照在调用期间不可变；
- 引擎失败给出可操作错误，不静默退回其它 ASR；
- 所有实时段落使用 segmentId、epoch 和递增 revision，旧结果不得覆盖新结果；
- 停止会议后等待所有排队任务、失败段落保留音频重识别、独立识别进程仍属后续增强。

## 8. 多说话人

- 麦克风来源默认可以标记为“我”；
- 系统声音中的远程参会人进行 embedding 聚类；
- 同一麦克风多人发言尽可能区分；新装默认声纹新建标签阈值为 **0.65**，已有自定义阈值不自动迁移，800ms 句末静音用于减少过敏断句并提供较长的声纹上下文；
- 只有高置信匹配才更新在线质心，避免一次边界误并持续污染后续判断；会议内修改阈值和最大人数从下一段生效；
- 初始使用匿名标签，不擅自猜测真实姓名；
- 顶部固定说话人栏；
- 改名同步更新全部相关段落和参会人名单；
- 支持合并两个说话人；
- 支持单段重新分配说话人；
- 会后使用完整音频重新校准；
- 人工指定优先于自动校准；
- 相似音色、重叠语音和远场收音允许存在误差，界面必须提供修正手段。

## 9. 术语库与整理视图

### 9.1 三级术语库

- 全局：个人常用产品名、缩写和行业术语；
- 项目：当前项目相关名词；
- 本场会议：参会人、临时名词和会议特定缩写。

说话人姓名确认后自动加入本场术语。

当前已实现**全局术语纠正表**：每行配置 `标准术语 = 常见误识别 1 | 常见误识别 2`，同时用于临时快照、整段定稿和纪要输入。它采用大小写不敏感、最长优先、英文整词边界和中英空白容忍的确定性替换，不做模糊猜词；原始模型文本仍单独保存。当前 SenseVoice GGUF 不支持 vocabulary/context prompt，因此不能把该功能描述为模型原生热词。项目级和本场会议级术语继承仍是后续方向。

### 9.2 双视图

- 原始逐字稿：保留识别原貌；
- 整理视图：可选去语气词、重复词和明显断句问题。

AI 清理默认关闭，必须单独授权。清理失败或超时使用原始文本，不影响后续 Word 生成。

## 10. 会议元数据

支持字段：

- 会议名称；
- 会议主题；
- 日期；
- 开始时间、结束时间和时长；
- 地点或线上平台；
- 主持人；
- 记录人；
- 实际参会人；
- 缺席人员；
- 会议类型；
- 关联项目；
- 保密级别；
- 备注。

日期和时间自动生成。地点、主持人等无法可靠推断的信息由用户填写。缺失字段在 Word 中显示“待补充”，不得由模型编造。

## 11. 历史会议与存储

- 本地会议列表和全文搜索；
- 查看、编辑和继续恢复会议；
- 原始音频可配置保留策略；
- 逐字稿与结构化纪要分开保存；
- 保存 Word 生成版本和所用模板版本；
- 重新生成不直接覆盖旧文件；
- 异常关闭后恢复未正常结束的会议；
- 打开 Word 文件和文件所在目录；
- 可导出原始逐字稿。

## 12. AI 与隐私

- 本地 ASR 和说话人分离不上传音频；
- 仅在用户主动使用 AI 清理、生成 Word，或主动发送包含会议内容的 DSH 对话草稿时发送必要文本；
- 点击“在 DSH 对话中整理”只创建草稿，不自动发送；已有草稿使用追加模式，不能静默覆盖；
- 生成任务与进度保存在 Host 内存，不包含音频；进程重启不恢复任务列表；
- 发送前说明使用的模型服务及数据范围；
- 默认优先发送整理后的必要内容，不发送原始音频；
- 使用 DSH 已配置的模型服务；Word 路径可固定独立纪要路由，插件不读取或另存模型密钥；
- 原始稿、人工修改和 AI 输出分开记录；
- 提供本地数据删除和录音保留设置。

## 13. 第一阶段非目标

- 实时翻译和同声传译；
- 跨会议声纹注册；
- 手机端远程麦克风；
- 任意浏览器字段听写；
- 多设备同时识别；
- 云端 ASR 作为默认方案；
- 音视频链接下载与导入；
- 用户自定义 Word 模板编辑器。

## 14. 核心验收场景

1. 在 Teams、腾讯会议或浏览器前台时，Ctrl+E 能唤起浮窗。
2. 浮窗出现时模型尚在加载，也能明确显示状态并在就绪后开始识别。
3. 两名远程参会人可以被区分并分别改名。
4. 改名后历史逐字稿、参会人名单和 Word 纪要一致。
5. 会议中拔掉指定麦克风后，自动回退且不丢失已保存内容。
6. 用户向上阅读历史时，新文字不会强制把界面拉回底部。
7. 点击完成后，最后一句话和待处理说话人结果全部完成才允许生成纪要。
8. 识别进程异常不会导致 DSH 退出，已保存内容可恢复。
9. 未启用 AI 功能时，会议文本不发送给云端模型。
10. 生成的 `.docx` 可在 Microsoft Word 和 WPS 正常打开，无修复提示。
11. Word 中的未知地点、负责人和截止时间不被模型编造。
12. 长会议文档不存在表格横向溢出、孤立标题、意外空白页和页码错误。
13. 点击生成后，即使关闭浮窗，独立工作台仍持续显示同一 Host 任务的阶段、字符进度和最终结果。
14. Provider 返回错误终态时显示实际 code/message，失败可重试，不能把认证、配额或网络错误统一误报为空内容。
15. 设置页可选择跟随 DSH 或明确纪要模型；模型选项必须来自 DSH 对话选择器的同一 `modelCatalog` 并保持分组与顺序，显式 Provider/Model/reasoningEffort 必须进入下一次实际请求，不改变 DSH 默认选择。
16. 模型持续返回思考或正文超过 120 秒时不被固定总时限中断；连续无数据达到配置值后才中止，并显示可操作的超时原因。
17. DSH 对话整理只追加完整草稿，不自动发送、不覆盖已有草稿；360px 工作台中任务与下载操作无横向溢出。

# dsh-meetscribe 产品需求与交互设计

更新日期：2026-11-21
状态：v0.1 产品规范；以 README 和 TESTING.md 记录的实际实现/验证状态为准

> 实现说明：本文保留产品目标和后续交互方向。v0.1 的 Ctrl+E 只切换浮窗，不自动开始/停止录音；浮窗位于 Harness overlay 内，不是独立系统置顶窗口。系统音频在当前宿主被权限拒绝。拖动、位置记忆、改键、会后声纹校准等仍属后续方向，不视为已交付功能。

## 1. 产品目标

dsh-meetscribe 是面向会议记录场景的 DeepSeek Harness 插件，核心能力包括：

- Ctrl+E 全局唤起 Orca 风格实时识别浮窗；
- 本地模型下载和离线语音识别；
- 麦克风与系统声音同时采集；
- 多说话人分离、改名和会后校准；
- 原始逐字稿与整理视图；
- 一键调用 DSH 大模型并生成正式 Word 会议纪要。

第一阶段不追求翻译、声纹注册、手机端和任意网页听写，优先保证会议识别、说话人管理和 Word 输出稳定可靠。

## 2. 主流程

1. 用户首次打开设置页，执行“一键配置”。
2. 插件下载推荐模型，检查麦克风、系统声音和快捷键。
3. 用户按 Ctrl+E，浮窗立即出现并显示模型状态。
4. 模型就绪后开始本地识别；加载期间不阻塞浮窗交互。
5. 实时显示不同说话人的临时文字和整句文字。
6. 用户在浮窗顶部修改说话人姓名，历史段落同步更新。
7. 用户可选填写会议地点、主持人、记录人等元数据。
8. 用户结束会议，系统处理完所有剩余音频和识别任务。
9. 用户点击“生成 Word 会议纪要”。
10. DSH 大模型生成结构化纪要内容，经校验后渲染为 `.docx`。
11. 用户打开 Word 文件或所在目录，也可重新生成新版本。

## 3. 快捷键

### 3.1 默认行为

| 操作 | 默认行为 |
| --- | --- |
| Ctrl+E | 唤起浮窗并开始识别；识别中再次按下则停止识别并保留内容 |
| Esc | 收起浮窗，不删除已识别内容 |
| 浮窗展开按钮 | 打开 DSH 完整会议面板 |
| 完成按钮 | 停止采集，清空处理队列，进入可生成纪要状态 |

开始、停止和显示浮窗的快捷键行为允许配置。

### 3.2 全局快捷键要求

- DSH 窗口内使用 DSH shortcuts 服务。
- DSH 最小化或其他应用前台时，由 Windows 桌面助手注册全局 Ctrl+E。
- 注册失败时明确提示快捷键被占用。
- Orca 与本插件同时运行时，不能同时全局占用 Ctrl+E；提供冲突解决和改键入口。
- 不因快捷键冲突影响已经保存的会议数据。

## 4. 实时识别浮窗

### 4.1 视觉原则

- 无边框、圆角、轻阴影，参考 Orca 的轻量效果。
- 系统级置顶，默认不抢占用户当前输入焦点。
- 支持拖动、缩放、最小化和展开。
- 跟随 DSH 深色或浅色主题。
- 记住浮窗位置、大小和所在显示器。
- 动画仅用于音量、识别状态和临时文字更新。
- 可选“共享屏幕时隐藏浮窗”。

### 4.2 展开状态布局

顶部区域：

- 识别状态指示灯；
- 会议名称；
- 会议时长；
- 麦克风和系统声音状态；
- 本地模型状态；
- 最小化、展开和关闭按钮。

说话人区域固定在其下方：

- 我、发言人 1、发言人 2等标签；
- 点击姓名内联修改；
- 管理说话人入口；
- 标签过多时横向滚动或展开，不挤压主要控制按钮。

正文区域：

- 时间、说话人和文字；
- 临时结果使用灰色；
- 整句结果使用正常前景色；
- 不确定说话人、人工修改和识别失败使用不同轻量状态；
- 用户向上滚动时停止自动跟随；
- 提供“回到最新”。

底部区域：

- 音量指示；
- 当前聆听或处理状态；
- 暂停、完成；
- “生成 Word 会议纪要”主按钮。

### 4.3 精简状态

仅显示：

- 识别状态和会议时长；
- 当前说话人和最近一句话；
- 展开、暂停和完成按钮。

### 4.4 取消与结束

必须区分：

- 取消当前尚未确认的一句话；
- 暂停会议；
- 结束整场会议；
- 删除会议记录。

结束会议不能等同于删除记录。危险操作需要明确确认。

## 5. 模型设置与初始化

### 5.1 一键配置

依次执行：

1. 根据语言和使用场景推荐模型组合；
2. 下载并校验模型；
3. 请求麦克风权限；
4. 检查系统声音回采；
5. 注册或验证全局快捷键；
6. 完成一次短录音、回放和识别测试；
7. 预热模型并进入可用状态。

任何一步失败都应给出具体修复入口，而不是只显示“初始化失败”。

### 5.2 模型管理

- 模型名称、用途、版本、文件大小和安装状态；
- 下载进度、失败重试和断点续传；
- 可配置镜像源；
- SHA-256 校验；
- 下载到临时文件，校验完成后原子替换；
- 自定义模型目录；
- 模型更新、损坏修复、重新下载和删除；
- 旧模型配置迁移；
- 模型许可证和来源记录；
- 手动卸载、会后卸载或常驻内存；
- GPU 开关和不可用时回退提示。

第一阶段通过“轻量会议包”“标准会议包”等预设隐藏模型组合复杂度，高级设置再展示各组件。

## 6. 音频采集

- 麦克风输入；
- Windows WASAPI 系统声音回采；
- 两路同时采集、分别显示状态；
- 麦克风和系统声音独立测试；
- 测试录音回放和识别结果；
- 默认设备与指定设备选择；
- 设备拔出后回退到系统默认设备并继续会议；
- 回声消除和重复内容去重；
- 按识别引擎要求重采样；
- 休眠恢复后重新初始化设备；
- 无法确认的音频中断区间在会议记录中标记。

## 7. 本地识别

推荐处理链路：

音频采集 → VAD 切句 → 流式 ASR 临时结果 → 整句 ASR 修正 → 标点与格式规范化 → 说话人关联 → 浮窗及持久化。

要求：

- 中文和中英混合识别；
- 临时结果持续更新；
- 停顿时提交整句；
- 停止会议后等待所有排队任务；
- 失败段落保留音频并可重新识别；
- 识别进程独立运行；
- 引擎异常不能导致 DSH 崩溃；
- 所有实时段落使用 segmentId 和递增 revision，旧结果不得覆盖新结果。

## 8. 多说话人

- 麦克风来源默认可以标记为“我”；
- 系统声音中的远程参会人进行 embedding 聚类；
- 同一麦克风多人发言尽可能区分；
- 初始使用匿名标签，不擅自猜测真实姓名；
- 顶部固定说话人栏；
- 改名同步更新全部相关段落和参会人名单；
- 支持合并两个说话人；
- 支持单段重新分配说话人；
- 会后使用完整音频重新校准；
- 人工指定优先于自动校准；
- 相似音色、重叠语音和远场收音允许存在误差，界面必须提供修正手段。

## 9. 术语库与整理视图

### 9.1 三级术语库

- 全局：个人常用产品名、缩写和行业术语；
- 项目：当前项目相关名词；
- 本场会议：参会人、临时名词和会议特定缩写。

说话人姓名确认后自动加入本场术语。

### 9.2 双视图

- 原始逐字稿：保留识别原貌；
- 整理视图：可选去语气词、重复词和明显断句问题。

AI 清理默认关闭，必须单独授权。清理失败或超时使用原始文本，不影响后续 Word 生成。

## 10. 会议元数据

支持字段：

- 会议名称；
- 会议主题；
- 日期；
- 开始时间、结束时间和时长；
- 地点或线上平台；
- 主持人；
- 记录人；
- 实际参会人；
- 缺席人员；
- 会议类型；
- 关联项目；
- 保密级别；
- 备注。

日期和时间自动生成。地点、主持人等无法可靠推断的信息由用户填写。缺失字段在 Word 中显示“待补充”，不得由模型编造。

## 11. 历史会议与存储

- 本地会议列表和全文搜索；
- 查看、编辑和继续恢复会议；
- 原始音频可配置保留策略；
- 逐字稿与结构化纪要分开保存；
- 保存 Word 生成版本和所用模板版本；
- 重新生成不直接覆盖旧文件；
- 异常关闭后恢复未正常结束的会议；
- 打开 Word 文件和文件所在目录；
- 可导出原始逐字稿。

## 12. AI 与隐私

- 本地 ASR 和说话人分离不上传音频；
- 仅在用户主动使用 AI 清理或生成纪要时发送必要文本；
- 发送前说明使用的模型服务及数据范围；
- 默认优先发送整理后的必要内容，不发送原始音频；
- 使用 DSH 已配置的模型，不在识别引擎中另存模型密钥；
- 原始稿、人工修改和 AI 输出分开记录；
- 提供本地数据删除和录音保留设置。

## 13. 第一阶段非目标

- 实时翻译和同声传译；
- 跨会议声纹注册；
- 手机端远程麦克风；
- 任意浏览器字段听写；
- 多设备同时识别；
- 云端 ASR 作为默认方案；
- 音视频链接下载与导入；
- 用户自定义 Word 模板编辑器。

## 14. 核心验收场景

1. 在 Teams、腾讯会议或浏览器前台时，Ctrl+E 能唤起浮窗。
2. 浮窗出现时模型尚在加载，也能明确显示状态并在就绪后开始识别。
3. 两名远程参会人可以被区分并分别改名。
4. 改名后历史逐字稿、参会人名单和 Word 纪要一致。
5. 会议中拔掉指定麦克风后，自动回退且不丢失已保存内容。
6. 用户向上阅读历史时，新文字不会强制把界面拉回底部。
7. 点击完成后，最后一句话和待处理说话人结果全部完成才允许生成纪要。
8. 识别进程异常不会导致 DSH 退出，已保存内容可恢复。
9. 未启用 AI 功能时，会议文本不发送给云端模型。
10. 生成的 `.docx` 可在 Microsoft Word 和 WPS 正常打开，无修复提示。
11. Word 中的未知地点、负责人和截止时间不被模型编造。
12. 长会议文档不存在表格横向溢出、孤立标题、意外空白页和页码错误。
